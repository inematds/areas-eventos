MÓDULO 2.1

Claude → Codex: separa el cerebro del modelo

Explicar por qué el lock-in está en el runtime y cómo el método Auditar → Adaptar → Probar → Handoff lleva el conocimiento del proyecto a un núcleo portátil.

0% 0 de 0

Qué es

El área Claude → Codex parte de una frase: "No migres tu cerebro. Separa el cerebro del modelo." El "cerebro" es todo lo que has acumulado en un proyecto: contexto, reglas, decisiones, tareas, skills, handoffs y memoria. Según la página, solo CLAUDE.md y AGENTS.md dependen del proveedor; todo lo demás es Markdown portátil, texto simple que cualquier agente puede leer. Cuando ese material está en una capa portátil dentro del proyecto, Claude Code, Codex CLI, Gemini o un modelo local en un contenedor se convierten únicamente en ejecutores, es decir, programas que hacen el trabajo a partir de esos archivos. Cambiar de modelo pasa a ser cambiar un borde, no el centro. El área reúne la tesis, el método, un curso de 3 rutas, un kit de scripts y megaprompts que lo ponen en práctica.

Por qué aprender

Los modelos cambian con frecuencia por precio, acceso o calidad. Si el conocimiento del proyecto está en el lugar correcto, cada cambio cuesta poco en vez de exigir una reconstrucción.

Conceptos clave

cerebro = contexto, reglas, decisiones, tareas, skills, handoffs y memoria; Markdown portátil; ejecutor; cambiar el borde, no el centro

Qué es

Lock-in significa quedar atado a un proveedor porque salir cuesta caro. La página afirma: "El lock-in no está en el modelo. Está en lo que dejaste dentro del runtime." Runtime es el programa que ejecuta el agente, como Claude Code o Codex CLI. Quien usa un asistente de código durante algunos meses ha acumulado instrucciones, memoria, skills, hooks y miles de sesiones en un formato que solo ese runtime puede leer. La página describe tres cambios: el lock-in es invisible hasta el día del cambio; el mismo conocimiento puede servirle a cualquier modelo; y pasas a tener menos dependencia y más control. El contenido perdura, el formato es desechable, y mezclarlos es lo que bloquea la migración.

Por qué aprender

El área es para quienes usan Claude Code o Codex en proyectos reales y temen cambiar de modelo. Entender dónde está la dependencia muestra qué debe salir del runtime antes de que el cambio sea obligatorio.

Conceptos clave

lock-in; runtime; CLAUDE.md, la memoria nativa y las sesiones JSONL son almacenamiento del trabajo, no el trabajo; contenido duradero, formato desechable

Qué es

El método tiene cuatro pasos, en este orden: Auditar, Adaptar, Probar y Handoff, «nunca implementar antes de auditar». Auditar consiste en hacer un inventario de solo lectura de los dos entornos de ejecución: skills, comandos, subagentes, hooks y MCP; cada skill se clasifica como reutilizable, adaptador, nativa o sin resolver. Adaptar consiste en dividir el CLAUDE.md: las reglas portátiles van al AGENTS.md, y lo que depende de un plugin, hook o menú de Claude queda en el archivo específico, que solo importa el contenido portátil. Probar consiste en abrir una sesión nueva y hacer cinco preguntas de continuidad: objetivo y criterio para darlo por listo, una regla con su archivo de origen, la última decisión, la próxima acción y los conflictos. Handoff consiste en registrar decisiones, pendientes, próximos pasos y rutas en un Markdown que la próxima sesión lea antes de actuar.

Por qué aprender

El orden evita el error más costoso: cambiar archivos antes de saber qué existe. Y la regla de prueba evita que confundas un archivo creado con conocimiento realmente utilizado.

Conceptos clave

Auditar → Adaptar → Probar → Handoff; MODE: audit; portátil × residuo; cinco preguntas de continuidad; que el archivo exista no es una prueba

Qué es

El núcleo portátil tiene siete ubicaciones, cada una con un responsable y una regla de actualización. AGENTS.md guarda reglas estables y el orden de lectura; context/overview.md, datos verificados con fuente y fecha; context/current-state.md, lo que funciona y lo que está pendiente; context/sources.md, de dónde viene cada información. context/decisions/ contiene una decisión aceptada por archivo; tasks/current.md indica el objetivo, el responsable, el criterio para darlo por listo y la próxima acción; handoffs/latest.md permite continuar en la próxima sesión. La página advierte que estos nombres son convenciones: ningún entorno de ejecución carga esas carpetas por sí solo; lo que indica que deben leerse es el orden de lectura al inicio de AGENTS.md. Cada información tiene un tipo: hecho, preferencia, hipótesis o decisión, y «provenance vence timestamp», es decir, el origen importa más que la fecha y nada se borra; se usa superseded_by.

Por qué aprender

Mezclar hechos con hipótesis, o decisiones con preferencias, hace que el agente repita errores antiguos y contradiga lo que ya se resolvió. El responsable y la fecha permiten promover una información al contexto aprobado, siempre con tu aprobación.

Conceptos clave

AGENTS.md; context/; decisions/; tasks/current.md; handoffs/latest.md; hecho, preferencia, hipótesis, decisión; provenance vence timestamp; secretos fuera del repositorio

Qué es

La página divide la decisión en tres niveles de esfuerzo, no en opiniones. El nivel 1 es importar en la app con un clic: es rápido, pero se limita a lo que acepta el otro lado; por ejemplo, el CLI de Codex no tiene importación nativa. El nivel 2 es migrar con el kit y un comando: ejecutar los scripts de agente-claude-codex para auditar, adaptar, instalar el núcleo, portar skills y probar. El nivel 3 es la capa personal portátil y duradera: el conocimiento vive en el proyecto y el entorno de ejecución se puede intercambiar. Mantener la independencia, es decir, no depender de ningún modelo específico, corresponde al nivel 3 y, según la página, es lo único que sobrevive al próximo cambio. Mantener la independencia no significa abandonar Claude: sigues eligiendo qué herramienta ejecuta cada tarea.

Por qué aprender

No todo el mundo necesita el nivel 3 ahora. La página indica cuándo conviene migrar ya, por costo, acceso o políticas, y cuándo conviene mantener la independencia, por ejemplo, si usas dos herramientas de ejecución o tienes trabajo de clientes.

Conceptos clave

Nivel 1: importar; Nivel 2: migrar con el kit; Nivel 3: capa personal portátil; migrar ahora × mantener la independencia; costo de no hacer nada

Qué es

El curso Claude → Codex: migra o mantén tu independencia es abierto, está en portugués y tiene versiones en inglés y español; según el programa, son 3 rutas, 18 módulos y 108 temas. La Ruta 1 cubre fundamentos y vocabulario; la Ruta 2 es el kit, comando por comando; y la Ruta 3 presenta seis proyectos sobre un sistema real. El kit agente-claude-codex combina bash y Markdown, y tiene tres formas de uso: scripts, mega-prompts y la plantilla del núcleo portátil. doctor.sh responde «¿mi entorno está listo?» y audit.sh guarda un informe de solo lectura; también están adapt-instructions.sh, init-core.sh, sync-skills.sh con polyskill, readback-test.sh, drift-report.sh y promover-memoria.sh. La página lo resume así: «El mejor primer paso es un proyecto tuyo, en modo audit».

Por qué aprender

El curso explica por qué y el kit hace el trabajo sin borrar nada: no copia en masa ni borra nada de ~/.claude o ~/.codex, e instalar una skill crea una copia de seguridad al lado. Empezar por la auditoría muestra en una sesión qué es portátil y qué depende de un hook.

Conceptos clave

curso de 3 rutas; kit agente-claude-codex; doctor.sh; audit.sh; mega-prompts A y B; Mapa del tema; área hermana Codex + Claude

MÓDULO 2.2

Codex + Claude: uno hace, el otro revisa

Explicar cómo usar Claude y Codex en el mismo proyecto, con los seis niveles del kit Use Both, la tarjeta de rutas y la diferencia entre claudex y Use Both.

0% 0 de 0

Qué es

La tesis del área Codex + Claude es: «Uno planifica, el otro critica. Usa ambos juntos». La idea es que Claude y Codex se complementan cuando cada uno hace una parte y el otro revisa el artefacto real, es decir, el archivo, el diff o la imagen de verdad. La regla que atraviesa todo: el segundo asistente recibe el mismo briefing y el artefacto real, nunca un resumen vago de lo que hizo el primero. La página es el punto de encuentro de INEMA para las dos herramientas y reúne los seis niveles del kit Use Both, la tabla de quién hace qué y las tarjetas de todos los cursos y proyectos. Para migrar de una a otra, el camino sigue siendo el área hermana Claude → Codex.

Por qué aprender

Es para quienes ya tienen Claude Code y Codex y no quieren elegir solo uno. Una segunda mirada de otro modelo detecta fallas que el autor suele pasar por alto.

Conceptos clave

uno hace, el otro revisa; artefacto real; mismo briefing; no es Claude o Codex; área hermana Claude → Codex

Qué es

El kit Use Both organiza el uso conjunto en seis niveles de flujo de trabajo, con prompts listos y dos skills pequeñas. El nivel 1 consiste en dejar que ambos debatan: uno escribe el plan y el otro critica el mismo archivo, solo leyendo, en un máximo de dos rondas. El nivel 2, opcional, consiste en generar imágenes, solo si hay una herramienta de imagen disponible en la sesión y después de verificar el acceso y el cobro. El nivel 3 consiste en dividir la construcción y la revisión: uno construye en una rama y el otro revisa el diff junto con el briefing y el resultado de las pruebas. El nivel 4 es el uso supervisado de la computadora, con la contraseña, los pagos y los envíos importantes bajo tu control; el nivel 5 es una meta con condición de parada, con éxito observable y límites de archivos, rondas y gasto. El nivel 6 es handoff y prime: el handoff guarda el estado en un archivo portátil y el prime hace que el siguiente asistente lea y verifique ese estado antes de continuar.

Por qué aprender

Los niveles forman una escalera: puedes empezar debatiendo un plan y avanzar solo cuando lo necesites. Cada nivel ya incluye el límite que evita gastos o acciones sin control.

Conceptos clave

debatir; generar imágenes; construir y revisar; uso supervisado de la computadora; meta con condición de parada; handoff y prime

Qué es

La tarjeta de rutas es una tabla del kit que indica, para cada tarea, quién hace la primera pasada, quién hace la segunda y cuál es el resultado esperado. Para planear el trabajo: Claude / Opus planea, Codex critica las premisas y el resultado es un plan con alcance y pruebas de aceptación. Para construir una función: Claude / Opus construye, Codex revisa el diff y el trabajo está listo cuando las pruebas pasan y los hallazgos están resueltos. Para abordar un bug difícil: Codex trabaja con una meta delimitada, pruebas y un punto de control humano. Para cambiar de sesión o de modelo: se crea una instantánea de handoff y prime verifica el estado actual. La página advierte que son «decisiones editoriales, no una clasificación medida de modelos»: prueba y quédate con la ruta que produzca mejores evidencias.

Por qué aprender

Tener una ruta inicial evita debatir desde cero en cada tarea. Saber que no es un benchmark evita tratarla como una verdad fija.

Conceptos clave

primera pasada; segunda pasada; resultado esperado; decisiones editoriales, no una clasificación; los modelos y el cobro cambian según la cuenta

Qué es

La página organiza cursos y proyectos en un camino: entender, migrar o mantener una postura agnóstica, usar ambos juntos y automatizar el debate. El vínculo común son los archivos Markdown del proyecto, como AGENTS.md, tasks y handoffs, que cualquier runtime puede leer. En ese camino aparecen dos herramientas diferentes. claudex es un plugin de Claude Code, es decir, software: Claude escribe el PLAN.md y Codex lo critica desde 3 ángulos, en un ciclo hasta llegar a LGTM o completar N rondas. Use Both es un kit de método con guía, prompts, plantillas y 2 skills, que cubre los seis flujos de forma manual o semiautomática. La página lo resume así: son complementarios; para un plan grande, claudex; para lo demás, como revisar un diff, definir una meta con condición de parada o cambiar de sesión, Use Both.

Por qué aprender

Saber en qué capa actúa cada herramienta evita instalar software para resolver un problema de método, o viceversa.

Conceptos clave

Entender → Migrar → Usar ambos → Automatizar el debate; claudex = software; Use Both = método; LGTM; complementarios

Qué es

La página presenta un caso real: quien tiene una suscripción de Codex puede usar su generador de imágenes, image_gen, al que en INEMA llaman «imagen 2.5». Actualmente, en INEMA, Claude Code ejecuta codex exec en modo no interactivo y le pide a image_gen un PNG en una carpeta; si Codex falla o no hay crédito, recurre al modelo local FLUX.2 klein. Cada generación consume crédito de la suscripción, por eso solo se ejecuta cuando está autorizada. Luego se revisa la imagen porque el texto en los bordes puede ser inventado. El kit propone aplicar el nivel 2 paso a paso: confirmar antes la herramienta y el cobro, nunca cambiar automáticamente a una API paga, guardar el archivo real en el proyecto y abrirlo al tamaño en que se usará. Según la página, la diferencia es esta: el sistema de INEMA funciona por lotes y automáticamente, con una alternativa local; el del kit es manual, con más verificación del costo y revisión.

Por qué aprender

Las imágenes generadas tienen un costo y errores visibles. Los dos enfoques muestran cómo equilibrar la automatización con la revisión antes de usar el archivo.

Conceptos clave

image_gen; codex exec; alternativa FLUX.2 klein; verificar antes, inspeccionar después; versiones paralelas en lugar de sobrescribir

Qué es

La página resume así el comienzo: «El mejor primer paso: un plan tuyo, revisado por el otro». Elige una tarea pequeña, escribe el briefing y el criterio de aceptación, pídele el plan a uno y la crítica al otro sobre el mismo archivo, en un máximo de dos rondas, y haz un handoff antes de cerrar la sesión. El área reúne seis cursos: Claude → Codex (PT, EN y ES), Codex Básico, Master Codex, iClaudeX, MakeClaudeX y DeepClaudeX. También reúne kits y referencias: agente-claude-codex, Use Both, claudex en GitHub, Codex Cheat Sheet y el Mapa del tema en INEMA.CLUB. La página menciona un video externo de Mark Kashef, que acompaña el kit Use Both, como fuente de las opiniones de su autor, sin benchmark; su resumen está en el archivo RESUMO-VIDEO.md del repositorio del kit.

Por qué aprender

Un primer ciclo breve muestra en la práctica el valor de una segunda mirada. Los cursos y kits indican dónde profundizar en cada etapa.

Conceptos clave

un plan tuyo, revisado por el otro; en un máximo de dos rondas; Codex Básico; Master Codex; iClaudeX; MakeClaudeX; DeepClaudeX; Use Both; claudex; Codex Cheat Sheet

MÓDULO 2.3

OSWork: qué edición es para ti

Explicar qué es OSWork, qué se construye con él y cuál de las cinco ediciones (v2, v6.2, v6, v5, Quick) se ajusta a la experiencia y al tiempo de cada persona.

0% 0 de 0

Qué es

OSWork se presenta como "IA como sistema de trabajo" y "del chat a tu entorno de agentes". Un agente es una IA que ejecuta tareas con herramientas y archivos, y no solo responde en una conversación. El curso enseña a organizar archivos, instrucciones, memoria y herramientas en un sistema de trabajo que puedes verificar. La frase central de la página es: "Tu próxima conversación puede empezar donde terminó la anterior." Para lograrlo, OSWork enseña a convertir pedidos sueltos en trabajo organizado: definir el objetivo, elegir el contexto, ejecutar una tarea pequeña y revisar el resultado. Empiezas en el chat y avanzas hasta un bot restringido y la operación supervisada en una VPS, un servidor alquilado en internet.

Por qué aprender

Sin organización, cada conversación con la IA empieza desde cero. Un sistema con archivos y reglas guarda lo que ya se decidió y permite comprobar el resultado.

Conceptos clave

sistema de trabajo; del chat al entorno de agentes; objetivo, contexto, tarea pequeña, revisión; bot restringido; VPS supervisada

Qué es

La página ofrece "cinco caminos para organizar tu trabajo con IA" y te pide elegir según tu experiencia y el tiempo disponible. OSWork v2 es el recorrido técnico. OSWork v6.2 es el recorrido completo, paso a paso. OSWork v6 es visual y para principiantes. OSWork v5 es para principiantes de 40 años o más. OSWork Quick va directo al punto. Según la página, hay cursos y videos en portugués, español e inglés; desde el acceso del área, v6.2 y v6 tienen enlaces propios en EN y ES.

Por qué aprender

Elegir la edición adecuada evita que abandones ante la primera terminal o te aburras con lo básico. La misma idea se presenta con distintos niveles de profundidad.

Conceptos clave

v2 técnico; v6.2 completo paso a paso; v6 visual para principiantes; v5 para principiantes de 40 años o más; Quick directo al punto

Qué es

OSWork v2 es el recorrido técnico: ocho módulos, cuatro rutas y 48 temas. Va del chat a la terminal y Codex, archivos, Skills, Git, un bot en Telegram y la operación supervisada en VPS, e incluye un kit de práctica. Los ocho módulos son: Modelos; Chat, Work y Desktop; Terminal y Codex en la práctica; Carpetas, Markdown y secretos; AGENTS, Skills y memoria; Git y GitHub sin perder trabajo; Telegram como interfaz de trabajo; y VPS desde cero y operación 24/7. OSWork v6.2 es ese mismo recorrido, adaptado para quienes están empezando: ocho módulos y 48 clases de unos 15 minutos, con instrucciones visuales paso a paso y un glosario de términos técnicos. En v2, el alumno marca los temas leídos, registra dudas, toma notas y exporta su recorrido; el progreso queda en el navegador y se separa por idioma.

Por qué aprender

Quien quiera llegar hasta los bots y servidores necesita el recorrido completo. v6.2 permite seguirlo incluso sin conocimientos técnicos previos.

Conceptos clave

v2: 8 módulos, 4 rutas, 48 temas, kit; v6.2: 48 clases de ~15 min, glosario; Codex; Skills; Git; Telegram; VPS

Qué es

Tres ediciones son para principiantes y no requieren instalación ni programación. OSWork v6 tiene siete clases de unos 15 minutos con pantallas de chat simuladas, ejemplos reales de antes y después e instrucciones visuales paso a paso; creas carpetas por tema, una ficha con tus reglas, una plantilla de solicitud y una rutina de revisión, sin instalar nada. OSWork v5 es para profesionales de 40 años o más con poca familiaridad con la IA: siete clases de 20 a 25 minutos para organizar carpetas, orientaciones, solicitudes reutilizables y una rutina de revisión, sin programar. OSWork Quick es la versión breve y visual para profesionales de 40 años o más: siete clases y alrededor de 77 minutos de estudio, con los mismos temas que v5 y menos texto. Quick también está disponible en video, con avatar y voz de Nei, ilustraciones y subtítulos SRT, en portugués, español e inglés.

Por qué aprender

Para quienes empiezan, el beneficio está en organizar y revisar, no en usar herramientas técnicas. Estas ediciones enseñan eso en poco tiempo.

Conceptos clave

v6: 7 clases de ~15 min, visual, sin instalar; v5: 7 clases de 20 a 25 min, 40+; Quick: 7 clases, ~77 min, también en video

Qué es

La página enumera lo que construirás en el recorrido: una carpeta de proyecto con entradas, salidas e instrucciones propias; una memoria de decisiones y errores, junto con una Skill reutilizable; un historial de Git para revisar y recuperar cambios; y un bot de consulta con datos ficticios y un plan de operación. Una Skill es un procedimiento empaquetado que el agente puede reutilizar; Git es un sistema que guarda versiones de los archivos. La sección del kit dice: "Tu primer entorno empieza con archivos reales." El kit reúne plantillas de AGENTS.md, memoria, decisiones, registro de errores, contrato de tareas, Skill de informes y plan de VPS, e incluye un bot de Python con una autoprueba sin conexión. El bot de práctica es determinista: no llama a un modelo de IA ni ejecuta mensajes como comandos.

Por qué aprender

Terminar con archivos concretos, y no solo con notas, permite reutilizar lo aprendido en el trabajo. Las plantillas del kit evitan empezar desde cero.

Conceptos clave

carpeta de proyecto; memoria de decisiones y errores; Skill; Git; bot de consulta con datos ficticios; kit ZIP; bot determinista

Qué es

La página recomienda: "Empieza con una tarea pequeña." Son tres pasos: elegir el primer módulo y comparar dos opciones disponibles en tu entorno; crear una carpeta de práctica y adaptar el contrato de tareas del kit; guardar el resultado, anotar una duda y volver a tu recorrido. En la sección "Antes de empezar", la página explica que puedes comenzar por los fundamentos sin programar y que los laboratorios técnicos presentan la terminal, Git y Python paso a paso. Puedes leer el contenido sin registrarte; las suscripciones, el uso de API y la contratación de una VPS son servicios aparte que cada alumno elige. El curso no promete un agente autónomo sin supervisión: enseña límites, verificación, registros y recuperación.

Por qué aprender

Una tarea pequeña permite obtener resultados rápido y ver qué falta organizar. Saber qué se paga aparte evita sorpresas.

Conceptos clave

tarea pequeña; carpeta de práctica; contrato de tareas; sin programar al inicio; lectura sin registro; servicios de pago por separado; operación supervisada
